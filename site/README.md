# The specification website

A static [Astro](https://astro.build) site that presents the OpenMessageBoard specification, served by Cloudflare
as static assets. It is the public face of [`spec/v0.1`](../spec/v0.1): a front page that states the case for an
open message board specification, and the specification itself, set as a document.

## What is generated and what is written

Nothing normative is copied into this directory. At build time the site reads:

| Page | Source |
|---|---|
| `/spec/v0.1/` and each numbered document | `spec/v0.1/*.md`, rendered as they are |
| `/spec/v0.1/requirements/` | `spec/v0.1/requirements.md` (generated by `schemas/generate.ts`) |
| `/spec/v0.1/examples/` | `spec/v0.1/examples/*.json` |
| Front page: design principles, document table | The tables in `spec/v0.1/README.md` |
| Front page: counts and the coverage figure | `spec/v0.1/requirements.json` and the generated table in the root `README.md` |

Only the front page's argument (`src/pages/index.astro`) is written here. Links inside the specification that
point at other documents become site links; links that point elsewhere in the repository become GitHub links
(`src/lib/rehype-spec.mjs`). BCP 14 key words are marked up so they can be styled.

## Sharing and agents

Every page is listed once, in `pages` (`src/lib/spec.ts`); the share images, the sitemap, `llms.txt` and the
Markdown twins are all made from that list, so a new page gets all of them.

| Address | What it is |
|---|---|
| `/og/<page>.png` | A 1200×630 share image per page, drawn at build time in the site's typeface (`src/lib/og.ts`) |
| `/llms.txt`, `/llms-full.txt` | What an agent should read, and the whole specification in one file (`src/lib/agents.ts`) |
| `/index.md`, `/spec/v0.1/<document>.md` | The Markdown twin of each page: the source text with links made absolute |
| `/spec/v0.1/requirements.json`, `/spec/v0.1/examples/<example>.json` | The catalogue and the worked examples as data |
| `/schemas/v0.1/…` | The generated JSON Schemas, without the test samples |
| `/sitemap.xml`, `/robots.txt` | For crawlers |

`worker.js` is the only code that runs at request time. It answers a page requested with `Accept: text/markdown`
with that page's Markdown twin, and adds a `Link` header naming the twin to every HTML page.

## Work on it

```bash
pnpm --filter @openmessageboard/site dev        # http://localhost:4321
pnpm --filter @openmessageboard/site build      # writes site/dist
pnpm --filter @openmessageboard/site typecheck
```

## Newsletter signup

The front page and `/newsletter/` have a signup form for updates by email. `newsletter.js` handles it in the
site's Worker:

- **Double opt-in.** `POST /api/newsletter/subscribe` stores the address as `pending` and emails a confirmation
  link; `GET /api/newsletter/confirm` marks it `confirmed`. Only the hash of the link's token is stored, and the
  link works for 7 days.
- **Built for a form anyone can type any address into.** One confirmation email per address per day, a daily cap
  on confirmation emails, a hidden field that scripts fill, a same-origin check, and the same answer whether or
  not an address is already subscribed.
- **Unsubscribe** is one click (`/api/newsletter/unsubscribe`, also the `List-Unsubscribe` header) and deletes
  the row.
- **Storage** is the D1 database `openmessageboard-newsletter` (`migrations/`): the address and three dates,
  nothing else. **Mail** is sent with Cloudflare Email Service from `newsletter@openmessageboard.com`.

Nothing here sends a newsletter yet: the list is collected, and sending an issue is a separate step.

```bash
pnpm --filter @openmessageboard/site test                                  # the handler, against real SQLite
pnpm --filter @openmessageboard/site exec wrangler d1 migrations apply NEWSLETTER --local
pnpm --filter @openmessageboard/site exec wrangler dev                     # emails are written to .wrangler/tmp/email
```

## Deploy

`wrangler.jsonc` describes static assets and the small Worker above, with a D1 database and an email sender for
the newsletter signup, and no secrets. Deploying applies any new database migration first.
It attaches the custom domains `openmessageboard.com` and `www.openmessageboard.com`. `omb.pub` belongs to the
public board server ([OMB-PUB.md](../implementations/cloudflare/OMB-PUB.md)).

```bash
pnpm --filter @openmessageboard/site run deploy
```
